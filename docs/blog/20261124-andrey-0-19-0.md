# Missing values in merged data

## TL;DR

- When you merge data from cohorts, studies, or sites that each measure their own variables, some
  pairs of variables are never observed in the same row. A test of such a pair, or a test given a
  variable that only another cohort measured, has no rows to read.
- The usual answers each claim something the data never showed. Answering such a test with p = 1
  deletes true edges and builds false colliders, answering p = 0 draws an edge between every pair
  never observed together, and EM takes their covariance from its model.
- Andrey 0.19.0 leaves such a test untested. A pair that no test decides is left out of the graph
  and listed as undecided, an edge that an untested set might have separated is flagged, and one
  notice says what happened. `possibly_separable="ambiguous"` reads no collider from a flagged edge.
- On simulated merged cohorts of 20 to 50 variables, PC's graph made fewer errors than the empty
  graph in every setting and found 0.87 to 0.95 of the true edges between variables observed
  together, about as many as on the complete data, where answering p = 1 found 0.21 to 0.34.
- Also in 0.19.0: DAS and CPCM are supported, and LGES, Regime-PCMCI, and the GCM, wGCM, and PCM
  tests arrive, experimental.

---

Large data sets are often built from smaller ones. A consortium pools the cohorts of several
hospitals, a registry links tables that different agencies collect, and a lab merges panels run
years apart. Each source measures a shared core and some variables of its own, so the merged table
has whole blocks of missing values where a source never measured a variable. The causal discovery
literature calls such data overlapping variable sets (Triantafillou and Tsamardinos, 2015).

Two variables that no source measured together are never observed in the same row, and nothing in
the data says whether they are dependent. PC and FCI read, for each test, the rows where its
variables are observed, test-wise deletion, so on merged data they meet tests with no rows. In
0.18.0 such a test stopped the fit with an error. This release is about what to answer instead.

## A test with no rows

Take the smallest merged data: two cohorts of 1,000 rows each from the fork `X <- Z -> Y`, one
cohort measuring `X` and `Z`, the other `Y` and `Z`. The truth has two edges, and `X` and `Y` are
independent given `Z`. No row observes `X` and `Y` together, so no test can check that, and a
collider `X -> Z <- Y` can give both cohorts the same distributions: from these rows alone, `X` and
`Y` could be adjacent or apart. Every test of `X` and `Y` has no rows, and so does every test of
`X` and `Z` given `Y`, or of `Y` and `Z` given `X`. What a method answers there decides its graph.

## What goes wrong with the usual answers

**p = 1** reads a test with no rows as independence. It removes `X - Y`, which happens to be right
here, and then `X - Z` given `Y` and `Y - Z` given `X`, which are true edges. On this case, PC with
p = 1 returned the empty graph on 20 of 20 seeds. Capped at `max_depth=0`, so that no edge is
tested given a third variable, it returned the collider `X -> Z <- Y` on every seed: `X` and `Y`
were separated without `Z`, and a separation the data never showed became a collider.

**p = 0** reads a test with no rows as dependence. It keeps `X - Y`, an edge no row supports: PC
returned the triangle on 20 of 20 seeds. On larger merged data every pair never observed together
becomes an edge, and those edges build false colliders, from about 100 to over 1,000 per fit in the
benchmark below.

**EM** fits a model of every column and fills in the missing values. No row holds the covariance of
`X` and `Y`, so EM takes it from the model it fits, and its answer about `X` and `Y` restates that
model rather than the data. In 0.18.0, EM ran on such data; 0.19.0 refuses them and names the pair.

**Dropping** every incomplete row leaves none. Dropping `X` or `Y` until every pair shares rows
loses a variable and its edges: on the benchmark's cohorts, PC then found 0.42 to 0.75 of the true
edges between variables observed together.

## What Andrey does

- **Not tested.** A test with fewer rows than it needs (`|S| + 4` for Fisher's z, with `|S|` the
  size of the conditioning set), or with no degrees of freedom left, is not tested: it never
  separates a pair and never confirms a link.
- **Undecided.** A pair that no tested query decides, such as one never observed together, is
  undecided: the graph leaves it out, `metadata["undecided_pairs"]` lists it, and no orientation
  reads it as adjacent or apart, so a triple whose ends are undecided makes no collider.
- **Possibly separable.** An edge is drawn when no tested query separated its pair, though an
  untested one might have. `metadata["possibly_separable"]` lists such edges. The flag says what
  the data could not check, not that the edge is false.
- **Ambiguous, if you ask.** With `possibly_separable="ambiguous"`, a triple with a flagged side is
  neither a collider nor a non-collider. The default, `"orient"`, reads it as any other triple.
- **One notice.** With the default `missing=None`, a fit on data with missing values logs one
  notice per process: it names test-wise deletion and when it is valid, and counts the pairs never
  observed together, the undecided pairs, and the flagged edges, naming them when there are at most
  five.
- **Grouped sums.** Merged cohorts fall into a few missingness patterns. With Fisher's z and
  Student's t, the tests compute their sums from each pattern's group of rows when that costs less
  than reading every row, and skip without building it a conditioning set that holds a variable
  never observed with the pair. On synthetic merged cohorts, `pc` ran 2.5 to 6.6 times faster with
  identical graphs, and with `max_depth=None` it finishes on 40 and 50 variables in about a second.

PC, FCI, CD-NOD, FCI-JCI, the Markov-blanket searches, PCMCI, PCMCI+, and LPCMCI follow these
rules; the [missing values guide](../docs/guides/missing-values.md#test-wise-deletion) gives each
method's details.

No row is complete. PC returns the true graph's CPDAG: the collider at `Z` comes from `X` and `W`,
which the first study observes together, and `Z -> Y` follows because `W` and `Y`, observed
together in the second study, are independent given `Z`. `X` and `Y` are undecided, listed and not
drawn. All three edges are flagged: each could have been separated by a set holding a variable
that only the other study measured, which no row can test. Here the flagged edges are true; on
larger merged data they include false ones. With `"ambiguous"`, the collider's sides are flagged,
so the graph keeps its edges and gives up its arrowheads. EM refuses the data and says what would
let it run.

## Measured on merged cohorts

We simulated data merged from cohorts: linear-Gaussian graphs with expected degree 3, a new graph
for each of 20 seeds, columns in units from 0.1 to 100, and three configurations, 20 variables in 3
cohorts, 40 in 8, and 50 in 6, with 37, 144, and 134 pairs never observed together. Each cohort
measures the shared core, some modules, and a few variables of its own. We ran PC and FCI with
Fisher's z and conditioning sets of up to 3 variables, with each answer to a test without enough
rows inside the same search. The table gives PC's errors (SHD, the structural Hamming distance,
mean over seeds) with no row observing every column and a tenth of the other values missing at
random; the empty graph's errors are the number of true edges.

| Variables (cohorts) | Empty graph | Andrey 0.19.0 | p = 1 | p = 0 | Complete data |
|---|---:|---:|---:|---:|---:|
| 20 (3) | 29.2 | 20.1 | 28.2 | 52.9 | 8.8 |
| 40 (8) | 62.7 | 49.2 | 66.0 | 187.8 | 14.7 |
| 50 (6) | 75.8 | 56.0 | 75.6 | 190.1 | 15.8 |

- PC's and FCI's graphs made fewer errors than the empty graph in all 12 settings without rows that
  observe every column. With p = 1, PC made about the empty graph's errors.
- Between variables observed together, PC found 0.87 to 0.95 of the true edges, against 0.88 to
  0.96 on the complete data and 0.21 to 0.34 with p = 1.
- In 1,204 PC and FCI fits on data with pairs never observed together, no such pair was drawn, and
  every one was listed as undecided.

The [release card](../docs/benchmarks/0.19.0.md#missing-values-in-merged-data) has every setting,
the intervals, dropping columns, the false colliders, and time series.

## What it costs

- **Undecided true edges are not drawn.** The true edges among the pairs never observed together,
  5.8 to 12.7 per fit, are listed and not drawn: no row can show them.
- **Some drawn edges are false, and the flag cannot yet tell which.** A quarter to a third of the
  drawn edges are false. Most join variables observed together whose separating set no cohort
  observes with them: a dependence of the variables observed together, drawn as a direct edge.
  Every such edge is flagged, but so are 98 to 100% of all drawn edges. These edges make most of
  the false colliders: PC drew 12.8 to 81.3 per fit in the table's setting, against 5.2 to 18.4 on
  the complete data.
- **"Ambiguous" trades arrowheads for safety.** It took PC's false colliders to at most 0.2 per fit
  and FCI's to at most 0.1, and it kept no true arrowhead either. PC's graph then made more errors
  than the empty graph in all six of its settings, and FCI's skeleton errors rose by 0.5 to 4.4,
  still fewer than the empty graph's. Keep the default when you read arrowheads, and use
  `"ambiguous"` when a false collider costs you more than a missing one.
- **A few bridging rows decide pairs, on few rows.** With 2 or 5% of the rows observing every
  column, every test has rows and the graph improves (SHD 17.6 against 20.1 on 20 variables), but a
  test across cohorts reads only those rows and can remove a true edge: with 2% bridging rows on 20
  variables, PC found 0.63 of the true edges between variables observed together, against 0.87
  without them.
- **Test-wise deletion assumes values missing completely at random.** Which cohort a row comes from
  is rarely random, and when whether a value is missing depends on other variables, deleting rows
  can mislead a method (Tu et al., 2019). Capping the conditioning sets with `max_depth` decides no
  pair: only rows that observe both columns do.

## Other highlights

- **DAS and CPCM are supported.** DAS made no more errors than its paper's code in any of 20
  settings from 10 to 200 variables with z-scored or rescaled columns, in a tenth to a fiftieth of
  the time. CPCM's pair test and graph search made as many errors as their paper's code on its
  pairs and graphs up to 8 variables, except in the gaps the card names, and the graph search ran
  about ten times faster. The [functional causal models post](20261103-andrey-0-13-0.md) and the
  [pairwise direction post](20261015-andrey-0-4-0.md) describe them.
- **LGES**, experimental: less greedy equivalence search, a score search beside GES that skips
  additions that one graph of the current class scores better without. In its authors' phase
  order and with position ties, it returned their graph in all 126 fits of the comparison.
- **Regime-PCMCI**, experimental: for one time series whose lagged links switch between a few
  persistent regimes, it returns the regime of each time step and one graph per regime. Every start
  that ran in both it and its authors' code gave the same weights and graphs.
- **The GCM, wGCM, and PCM tests**, experimental: regression-based conditional-independence tests
  for every method that takes `indep_test`.
- **Lists of targets.** `target` takes a list of columns on IAMB, Inter-IAMB, MMPC, and ICP: one
  call returns one result per target and shares the search's setup.
- **Options with character.** Each option added or changed in this release states what each value
  favors and what it gives up, with the measurements behind it.
