# Missing values in merged data

## TL;DR

- When you merge data from cohorts, studies, or sites that measure different variables, some pairs
  of variables are never observed in the same row. A test of such a pair, or a test conditioned on
  a variable measured only by another cohort, has no rows to use.
- The usual answers each claim something the data did not show. Answering such a test with p = 1
  deletes true edges and creates false colliders; answering p = 0 draws an edge between every pair
  never observed together; EM takes their covariance from its model.
- Andrey 0.19.0 leaves such a test untested. A pair that no test decides is omitted from the graph
  and listed as undecided. An edge that an untested conditioning set might have separated is
  flagged, and one notice reports what happened. `possibly_separable="ambiguous"` reads no
  collider from a flagged edge.
- On simulated merged cohorts of 20 to 50 variables, PC's graph made fewer errors than the empty
  graph in every setting and found 0.87 to 0.95 of the true edges between variables observed
  together. This was about as many as on the complete data; answering p = 1 found 0.21 to 0.34.

---

Large data sets are often built from smaller ones. A consortium pools cohorts from several
hospitals, a registry links tables collected by different agencies, and a lab merges panels run
years apart. Each source measures a shared core and some variables of its own. The merged table
therefore has whole blocks of missing values where a source never measured a variable. The causal
discovery literature calls such data overlapping variable sets (Triantafillou and Tsamardinos,
2015).

Two variables that no source measured together are never observed in the same row, so no test can
read whether they are dependent. For each test, PC and FCI use the rows where all its
variables are observed, a procedure called test-wise deletion. On merged data, some tests have no
rows. In 0.18.0, such a test stopped the fit with an error. This release changes how we handle
those tests.

## A test with no rows

Consider the smallest merged data set: two cohorts of 1,000 rows each from the fork `X <- Z -> Y`,
one cohort measuring `X` and `Z`, the other `Y` and `Z`. The true graph has two edges, and `X`
and `Y` are independent given `Z`. No row observes `X` and `Y` together, so no test can check
that independence. A collider `X -> Z <- Y` can give both cohorts the same distributions: these
rows alone cannot establish whether `X` and `Y` are adjacent. Every test of `X` and `Y` has no
rows, as does every test of `X` and `Z` given `Y`, or of `Y` and `Z` given `X`. How a method
handles these tests determines its graph.

## What goes wrong with the usual answers

**p = 1** treats a test with no rows as evidence of independence. It removes `X - Y`, which happens
to be correct here, and then removes the true edges `X - Z` given `Y` and `Y - Z` given `X`.
In this case, PC with p = 1 returned the empty graph on 20 of 20 seeds. With `max_depth=0`, so that
no edge is tested given a third variable, it returned the collider `X -> Z <- Y` on every seed:
`X` and `Y` were separated without `Z`, and a separation the data never showed became a collider.

**p = 0** treats a test with no rows as evidence of dependence. It keeps `X - Y`, an edge no row
supports: PC returned the triangle on 20 of 20 seeds. On larger merged data sets, every pair never
observed together becomes an edge. Those edges create false colliders, from about 100 to over
1,000 per fit in the benchmark below.

**EM** fits a model of every column and fills in the missing values. No row provides an observation
of `X` and `Y` together from which to estimate their covariance, so EM takes it from the fitted
model. Its answer about `X` and `Y` therefore restates that model rather than the data. In 0.18.0,
EM ran on such data; 0.19.0 refuses them and names the pair.

**Dropping** every incomplete row leaves none. Dropping `X` or `Y` until every pair shares rows
loses a variable and its edges. On the benchmark's cohorts, PC then found 0.42 to 0.75 of the true
edges between variables observed together.

## What Andrey does

- **Not tested.** A test with fewer rows than it needs (`|S| + 4` for Fisher's z, with `|S|` the
  size of the conditioning set), or with no degrees of freedom left, is not tested. It never
  separates a pair or confirms a link.
- **Undecided.** A pair that no tested query decides, such as a pair never observed together, is
  undecided. The graph omits it, and `metadata["undecided_pairs"]` lists it. No orientation treats
  it as adjacent or nonadjacent, so a triple whose ends are undecided cannot become a collider.
- **Possibly separable.** An edge is drawn when no tested query separated its pair, though an
  untested query might have. `metadata["possibly_separable"]` lists such edges. The flag indicates
  what the data could not check; it does not mean the edge is false.
- **Ambiguous, if you ask.** With `possibly_separable="ambiguous"`, which PC, FCI, CD-NOD, FCI-JCI,
  the Markov-blanket searches, and PCMCI+ take, a triple with a flagged side is neither a collider
  nor a non-collider. The default, `"orient"`, treats it as any other triple.
- **One notice.** With the default `missing=None`, a fit on data with missing values logs one
  notice per process. It names test-wise deletion and explains when it is valid. It also counts
  the pairs never observed together, the undecided pairs, and the flagged edges, naming them when
  there are at most five.
- **Grouped sums.** Merged cohorts have a few missingness patterns. With Fisher's z and Student's
  t, the tests compute sums from each pattern's group of rows when that costs less than reading
  every row. They also skip a conditioning set before building it if it contains a variable never
  observed with the pair. On synthetic merged cohorts, `pc` ran 2.5 to 6.6 times faster with
  identical graphs. With `max_depth=None`, it finishes on 40 and 50 variables in about a second.

PC, FCI, CD-NOD, FCI-JCI, the Markov-blanket searches, PCMCI, PCMCI+, and LPCMCI leave such tests
untested, list undecided pairs, and flag possibly separable edges; the
[missing values guide](../docs/guides/missing-values.md#test-wise-deletion) gives each method's
details.

No row is complete. PC returns the true graph's CPDAG: the collider at `Z` comes from `X` and `W`,
which the first study observes together, and `Z -> Y` follows because `W` and `Y`, observed
together in the second study, are independent given `Z`. `X` and `Y` are listed as undecided and
are not drawn.

All three edges are flagged: each could have been separated by a conditioning set containing a
variable measured only by the other study, which no row can test. Here the flagged edges are true;
on larger merged data sets, they include false edges. With `"ambiguous"`, the collider's sides are
flagged, so the graph keeps its edges but loses its arrowheads. EM refuses the data and explains
what would let it run.

## Measured on merged cohorts

We simulated data merged from cohorts using linear-Gaussian graphs with expected degree 3, a new
graph for each of 20 seeds, and columns in units from 0.1 to 100. We used three configurations:
20 variables in 3 cohorts, 40 in 8, and 50 in 6, with 37, 144, and 134 pairs never observed
together. Each cohort measures the shared core, some modules, and a few variables of its own.

We ran PC and FCI with Fisher's z and conditioning sets of up to 3 variables, using each answer to
a test without enough rows within the same search. The table gives PC's errors (SHD, the structural
Hamming distance, averaged over seeds) with no row observing every column and a tenth of the other
values missing at random. The empty graph's errors equal the number of true edges.

| Variables (cohorts) | Empty graph | Andrey 0.19.0 | p = 1 | p = 0 | Complete data |
|---|---:|---:|---:|---:|---:|
| 20 (3) | 29.2 | 20.1 | 28.2 | 52.9 | 8.8 |
| 40 (8) | 62.7 | 49.2 | 66.0 | 187.8 | 14.7 |
| 50 (6) | 75.8 | 56.0 | 75.6 | 190.1 | 15.8 |

- PC's and FCI's graphs made fewer errors than the empty graph in all 12 settings without rows
  observing every column, FCI's counted on the skeleton. With p = 1, PC made about as many errors as
  the empty graph.
- Between variables observed together, PC found 0.87 to 0.95 of the true edges, compared with 0.88
  to 0.96 on the complete data and 0.21 to 0.34 with p = 1.
- In 1,204 PC and FCI fits on data with pairs never observed together, no such pair was drawn, and
  every such pair was listed as undecided.

The [release card](../docs/benchmarks/0.19.0.md#missing-values-in-merged-data) reports every setting
and the intervals, along with results for dropping columns, false colliders, and time series.

## What it costs

- **Undecided true edges are not drawn.** True edges between pairs never observed together,
  5.8 to 12.7 per fit, are listed and not drawn: no row can show them.
- **Some drawn edges are false, and the flag cannot yet tell which.** A quarter to a third of the
  drawn edges are false. Most join variables observed together whose separating set no cohort
  observes with them. Their dependence is drawn as a direct edge. Every such edge is flagged, but
  so are 98 to 100% of all drawn edges. These edges create most of the false colliders: PC drew
  12.8 to 81.3 per fit in the table's setting, compared with 5.2 to 18.4 on the complete data.
- **"Ambiguous" trades arrowheads for safety.** It reduced PC's false colliders to at most 0.2 per
  fit and FCI's to at most 0.1, but the share of true arrowheads it found fell to 0.00. PC's graph
  then made more errors than the empty graph in all six of its settings, and FCI's skeleton errors
  rose by 0.5 to 4.4, still fewer than the empty graph's. Keep the default when you interpret
  arrowheads, and use `"ambiguous"` when a false collider costs you more than a missing one.
- **A few bridging rows decide pairs using few observations.** With 2 or 5% of the rows observing
  every column, every test has rows and the graph improves (SHD 17.6 compared with 20.1 on 20
  variables). However, a test across cohorts uses only those rows and can remove a true edge:
  with 2% bridging rows on 20 variables, PC found 0.63 of the true edges between variables
  observed together, compared with 0.87 without them.
- **Test-wise deletion assumes values missing completely at random.** Which cohort a row comes from
  is rarely random. When missingness depends on other variables, methods applied to the observed
  rows can reach wrong conclusions (Tu et al., 2019). Capping the conditioning sets with `max_depth`
  decides no pair: only rows that observe both columns do.
